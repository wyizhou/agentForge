# {{PROJECT_NAME}} project instructions

## Working agreement

- Inspect the repository and existing changes before editing.
- Read `SKILLS.md` and load a Skill only when its trigger matches.
- Preserve unrelated work and avoid destructive Git operations.
- Understand existing behavior before changing it.
- Add or update tests for behavior changes.
- Update documentation when architecture or product behavior changes.
- Run the repository's relevant tests, lint, type checks, and build before
  delivery.
- Report validation evidence, skipped checks, and remaining risks.
- Do not commit, push, merge, deploy, or create remote resources unless the user
  requests that external effect.

For complex work, write down scope, decisions, progress, and acceptance evidence
in the repository rather than relying on conversation history alone.

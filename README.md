# agentForge

agentForge 是一个可直接下载使用的静态 Loop Engineering 项目脚手架。它不包含生成器、安装器、初始化脚本、CI、预装 linter 或测试框架，也不要求执行 Bootstrap 命令。

下载仓库归档并解压到项目目录后，AI 编程工具即可通过仓库内的持久化文件恢复规则、偏好和任务状态。首次进行仓库工作时，AI 会依据 [`AGENTS.md`](AGENTS.md) 检查 Git；缺少 Git 或尚未初始化仓库时，必须分别取得用户批准后才能安装或执行 `git init`。

## 文件结构

```text
AGENTS.md                  # AI 的权威启动与交付协议
CLAUDE.md                  # Claude Code 对 AGENTS.md 的引用入口
rules.md                   # 仅由人工批准加入的项目硬约束
memory.md                  # AI 维护的跨会话稳定事实与偏好
PLANS.md                   # 长期 Roadmap、阶段、任务和并行批次
CHANGELOG.md               # 正式发布版本及变更摘要
docs/exec-plans/           # 每项仓库工作的计划、检查点和验证证据
└── tech-debt-tracker.md   # 由人工决定是否处理的技术债候选
src/                       # 功能的开发实现目录
tests/                     # 与开发实现对应、按功能划分的根目录测试
skills/                    # 只在当前仓库内按需读取的项目 Skill
references/                # 用户主动生成和维护的可复用专题知识
```

模板使用根目录下互为同级的 `src/` 和 `tests/`：生产功能在 `src/` 中实现，对应测试放在 `tests/<feature-slug>/`。模板不使用 `product/` 存放代码或测试，也不预设 `dist/`；未来项目只有在实际技术栈需要构建产物时，才自行决定是否增加相应目录。

## Loop 状态恢复

每个新的上下文窗口从 `AGENTS.md` 开始，并依次恢复 `rules.md`、`memory.md`、`PLANS.md` 和匹配的活动执行计划。任务步骤只记录在执行计划中；`memory.md` 仅保存稳定信息和活动计划链接，避免多份状态互相漂移。

项目 Skill 使用 `skills/<name>/SKILL.md`，不得安装、复制或链接到用户级或全局 Skill 目录。

`references/` 用于保存需要反复查询、搜索或思考的稳定专题知识，例如第三方 API、数据库性能、编码风格或组织规范。该目录初始只有 `.gitkeep`；AI 不会自动生成内容，只有用户主动要求时才会创建或更新相应资料。新任务只读取与目标相关的 reference，避免把整个知识库加载进上下文。

`memory.md` 保存短小的偏好、项目事实和任务续接指针；`references/` 保存可复用的专题正文；`rules.md` 保存经过人工批准并必须执行的硬性约束；`skills/` 保存可执行工作流；`PLANS.md` 保存未来规划；exec plan 保存当前任务状态。这些内容不得相互替代。

## 冻结验证合同

`AGENTS.md` 统一规定 Validator 如何裁决，每个 exec plan 则保存当前任务具体要验证的冻结合同。初始合同随用户任务或计划批准自动冻结，不增加一次额外确认，也不建立独立合同目录。

合同通过 `AC-*`、`INV-*`、`TM-*`、`EX-*` 和 `GATE-*` 区分验收标准、行为不变量、威胁模型、排除项和检查门禁。Validator 可以创造新的测试方法，但每个阻塞发现必须绑定已有标准；超范围发现只能作为建议，合同含糊时返回 `INCONCLUSIVE`。冻结合同只有经过人工明确批准才能升级版本，升级后旧验证结果失效。

## Roadmap 与并行开发

`PLANS.md` 使用“阶段 → 子项目 → 叶子任务”组织未来开发。远期阶段只保留目标和依赖；当前阶段经人工批准后才展开任务、验收目标、写入范围和并行批次。详细 exec plan 只在任务进入 ready batch、即将开始修改仓库时创建，因此不会因即时规划而限制并行开发。

同一批次的并行任务必须依赖已满足、写入范围不重叠且共享接口已冻结。每项任务使用独立本地分支和 Git worktree，由主协调 Agent统一维护 Roadmap 和协调状态。Worker 先经过任务级独立验证，集成后再进行完整回归验证；只有两层验证通过才会勾选 Roadmap。

执行中发现但不影响当前正确性、安全和交付的问题可以记录为技术债候选。AI 不会自动安排技术债，只有人工可以接受、排序或提升为 Roadmap/exec plan。

## 动态 Agent 选档

subagent 的模型能力和推理强度分别使用 `low`、`medium`、`high` 抽象档位，不绑定具体平台或模型名称。主 Agent选择满足风险和验收要求的最低充分档位；能力不足时使用全新 Agent逐级升级，达到 `high/high` 仍失败则停止并标记 `blocked`。

平台不能显式选档时记录 `platform-default`，通过缩小任务范围、明确验收、完整检查和独立 Validator 补偿。Validator 能力不得低于对应 Worker。

## 工程门禁

空模板不猜测技术栈。首次引入可执行代码时，默认在 `src/` 中开发实现，并在同一任务中建立适合该项目类型的 linter 和测试框架。每项功能使用根目录下独立的 `tests/<feature-slug>/` 目录，先固定测试预期再实现功能。后续交付必须运行所有适用检查，且不得为获得绿灯而弱化测试或 lint 规则。

产生结果变更的任务只有通过全新、只读且独立的 Validator 后才能完成。并行工作先进行任务级验证，再在集成后运行完整 lint、测试和跨任务回归。

## 版本发布

普通任务不创建版本。只有用户明确要求发布时，才使用人工批准的版本号把 `CHANGELOG.md` 中的 `Unreleased` 内容整理为正式版本，并留下对应更新摘要。
